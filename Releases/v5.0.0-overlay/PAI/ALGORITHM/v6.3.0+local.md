# Algorithm v6.3.0+local

This file is the entry-point Algorithm doctrine when
`PAI/ALGORITHM/LATEST` reads `6.3.0+local`. It defines the local
Algorithm as **v5's `v6.3.0.md` doctrine plus the fork's
ENUMERATE→OFFER phase-exit gate** at the OBSERVE→THINK boundary.

This wrapper does NOT modify `v6.3.0.md`. It is a load-order document
only — it instructs the agent to load both files before executing the
Algorithm.

## MANDATORY LOAD SEQUENCE — read BOTH files before entering OBSERVE

1. **Read `PAI/ALGORITHM/v6.3.0.md` in full.** This is v5's vanilla
   Algorithm doctrine — the source of truth for phases (OBSERVE, THINK,
   PLAN, BUILD, EXECUTE, REFLECT, LEARN), ISCs, capability vocabulary,
   gates, and output formats. Internalize it but do NOT yet start
   executing.

2. **Read `PAI/ALGORITHM/askuq-gate.md` in full.** This is the fork's
   addendum — adds an AskUserQuestion ENUMERATE→OFFER hard gate at the
   OBSERVE→THINK boundary. Internalize it as part of OBSERVE's exit
   criteria, alongside v6.3.0's existing OBSERVE→THINK gates (e.g. the
   Capability-Name Audit Gate at v6.3.0.md:65).

3. **Now execute the Algorithm**, applying v6.3.0's phases with the
   addendum's gate enforced at the OBSERVE→THINK transition.

Both files together constitute the Algorithm for this run. The addendum
does not replace v6.3.0; it stacks one additional gate that v6.3.0
does not currently enforce.

## Adding further addenda

Drop the addendum file at `PAI/ALGORITHM/<name>-gate.md` and add a
mandatory load step above. Keep addenda single-purpose — each one
enforces exactly one phase-exit gate or one targeted rule. Multiple
addenda are loaded in the order listed here.
